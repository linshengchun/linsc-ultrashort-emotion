# LINSC超短情绪复盘系统

面向只做多、持股约2—3日的A股超短交易者。项目支持在网页选择交易日后手动生成或覆盖报告，并把结果保存为 Markdown、JSON 与 PDF 供阅读和归档。

## 工作方式

本地运行默认调用本机 Codex；线上版本使用可配置的大模型 API。客观指标始终由程序计算，大模型负责题材叙事、情绪周期与文字报告。

1. 网页选择交易日，点击“使用Codex生成本日报告”或“重新生成本日报告”。
2. 本地回环服务先准备统一数据缓存：正式报告只接受收盘终态，自动补齐D日前60个交易日与D日的61日窗口；缺失或未完成的FTShare分页从断点续取，随后计算确定性指标并启动 `codex exec`。
3. 市场叙事采集层独立缓存韭研公社页面、个股事件和题材传播记录；问财回退结果也按交易日独立缓存；报告生成器只读取本地缓存。
4. Codex按固定Schema输出报告，程序完成结构校验、索引更新和紧凑版PDF渲染。
5. Markdown与PDF通过SFTP上传到 `root@43.134.1.133:/root/linsc-astock/reports/`，并进行远程SHA-256校验。
6. 同一交易日重新生成时直接覆盖本地和服务器上的同名报告。
7. 线上多模型API模式尚未启用。

盘中叙事监控不是生成报告的前置条件；若盘中没有启动监控且同日叙事缓存不完整，网页点击生成报告时会先执行同日韭研公社叙事补抓。数据源覆盖和缓存边界见 [`docs/data-cache.md`](docs/data-cache.md)。

报告文件位于：

- `data/reports/YYYY-MM-DD.md`：正式 Markdown 报告。
- `data/reports/YYYY-MM-DD.json`：网页摘要和关键指标。
- `public/reports/YYYY-MM-DD.pdf`：本地生成后上传的正式 PDF。
- `public/reports/index.json`：静态归档索引。

### 数据源分层

| 数据层 | 主来源 | 后备顺序 | 使用原则 |
| --- | --- | --- | --- |
| 客观行情层 | FTShare-MCP V1 | 同花顺金融数据API/问财 → AShareHub → 东方财富；a-stock-data按字段作补充/交叉核验 | a-stock-data是多源聚合工具而非独立行情供应商；须记录实际底层来源、交易日和字段口径，未经核验不得覆盖主源或作为正式结论依据。原始行情按交易日缓存；成交额、MA60、近5日、连板和昨日涨停反馈由本地程序确定性计算 |
| 竞价/早盘证据层 | 同花顺短线风向标竞价基准＋FTShare V1事件时点与分钟成交占比 | 当日同花顺竞价快照 | 只记录实际取得的时点证据；历史全市场竞价或分钟价格不能回放时留空，不由日线反推 |
| 题材归因层 | 同花顺问财 | 东方财富题材 → a-stock-data提供的同花顺/东财题材字段（核明实际来源后使用） → 公开市场资料 | 用于涨停原因、概念归类和题材事件树；聚合工具的标签不能冒充已核实的事件原文 |
| 市场叙事采集层 | 韭研公社 → 本地事件缓存 | 选股通 → 财联社 → 市场公开讨论 | 原始内容不丢失；以个股事件卡记录小作文、预期差、传播强度、想象空间与价格反馈，不做公告一致性核验 |
| 分析判断层 | LINSC规则引擎 | 最近5日静态报告 | 把客观数据、题材结构和核心反馈合成为周期、子状态、赚钱效应及接力难度 |

`a-stock-data`（[项目地址](https://github.com/simonlin1212/a-stock-data)）纳入补充数据源清单，定位为字段级补充与交叉核验，不作为独立数据供应商。当前仅完成方案登记，尚未接入本项目自动采集脚本，也未通过 LINSC 口径验收；接入时必须保存其实际底层来源，不调用其通达信盘后数据路径，并按现有数据冲突规则处理。

当前 FTShare 账户未开通 v2 接口权限，项目固定使用已授权的 FTShare v1 工具；不得调用 v2 批量 K 线或涨跌停事件工具作为必需依赖。v1 返回截断、权限不足或字段缺失时，只对缺失字段按下方规则回退。

当 FTShare 某个接口或字段出现无记录、权限不足、超时、截断或交易日不匹配时，按“同花顺问财 → AShareHub → 东方财富”逐字段回退。回退数据必须带交易日、查询语句、返回时间和原始结果，并重新执行 LINSC 股票范围过滤；FTShare 已返回的可靠字段不被覆盖，无法形成同一口径时保留“—”，不使用相邻日期或未过滤的全市场数字倒填。

### 固定边界

- 股票范围排除名称含 `ST`、`*ST` 和北交所，纳入沪深主板、创业板与科创板。
- 报告不展示内部“数据完整性”模块；覆盖不足时在生成流程内部阻止或降级结论。
- 题材和个股消息按市场正在交易的叙事记录，不与公告做一致性核验，也不把小作文写成已经确认的事实。
- 不包含高标卡异动、绕异动模块。
- 不输出泛化的“次日操作”；只保留次日 1进2 的条件预判。
- 模块二、模块三的近5日对比表统一按交易日期倒序展示（最新交易日在第一行，最早交易日在最后一行）。

## 本地运行

```bash
npm install
npm run dev
```

构建和校验：

```bash
npm run build
```

启动本地网页与Codex生成服务：

```bash
npm run dev:local
```

默认网页地址由开发服务器输出，本地生成服务固定监听 `http://127.0.0.1:4317`，只接受来自 `localhost` 或 `127.0.0.1` 的网页请求。

也可以不经过网页，手动生成指定日期：

```bash
npm run data:prepare -- --date 2026-08-28 --for-report
npm run report:generate -- --date 2026-08-28 --provider codex
npm run report:prepare
npm run report:pdf -- --date 2026-08-28 --output public/reports/2026-08-28.pdf
npm run report:upload -- --date 2026-08-28
```

同日再次执行 `data:prepare -- --for-report` 会直接命中已完成日期，只续传缺口；当日15:10前不会把盘中缓存当作正式报告终态。可用 `npm run data:health -- --date 2026-08-28` 检查本地缓存、61日窗口、确定性指标、早盘证据与FTShare V1在线接口。

市场叙事采集器默认先读取当日客观涨停池，将涨停票写入 `priorityStocks`，再按队列采集叙事；采集过程单线程、请求间隔4秒。遇到403、429、验证码或查阅次数限制会停止本轮并保留已有缓存，不自动重试或规避平台限制。

### 盘中持续监控采集

每天开盘前后，双击项目根目录的：

```text
启动盘中持续监控采集.cmd
```

启动器会打开韭研公社专用浏览器。确认登录后回到命令窗口按回车，程序开始每60秒查询FTShare涨停池；第一批新涨停立即触发叙事采集，后续按30分钟冷却批量执行，每日最多8批，15:10后自动结束。登录资料只保存在本机被Git忽略的 `.local/` 目录，不保存账号密码。

也可以使用命令行启动：

```bash
npm run narratives:watch
```

需要停止时在监控窗口按 `Ctrl+C`。盘中没有运行监控也不影响盘后报告：点击生成报告时仍会自动执行一次同日补抓。

首次使用 PDF 渲染和SFTP上传功能时安装依赖：

```bash
npm run setup:python
```

## GitHub配置

本地Codex模式不需要在项目中配置大模型API密钥，但必须安装并登录Codex。可选环境变量：

- `CODEX_CLI`：Codex启动程序路径；Windows 默认使用 `codex.exe`，其他系统默认使用 `codex`。
- `CODEX_MODEL`：本地生成时使用的Codex模型；留空时沿用当前Codex配置。
- `CODEX_REASONING_EFFORT`：本地生成推理强度，默认 `high`；需要更深分析时可改为 `xhigh`。
- `LINSC_PYTHON`：PDF渲染使用的Python路径；Codex桌面环境会优先使用内置文档运行环境，否则使用 `python`。
- `LINSC_LOCAL_GENERATOR_PORT`：本地生成服务端口，默认 `4317`。
- `NEXT_PUBLIC_GENERATOR_URL`：网页调用的生成服务地址；开发模式默认 `http://127.0.0.1:4317`。
- `LINSC_UPLOAD_HOST`：报告服务器，默认 `43.134.1.133`。
- `LINSC_UPLOAD_USER`：SFTP用户，默认 `root`。
- `LINSC_UPLOAD_DIR`：服务器报告目录，默认 `/root/linsc-astock/reports`。
- `LINSC_UPLOAD_PASSWORD_FILE`：密码文件，默认项目根目录的 `key.txt`。
- `LINSC_UPLOAD_KNOWN_HOSTS`：服务器主机密钥文件，默认 `config/ssh_known_hosts`。

`key.txt` 已被Git忽略。密码只在上传进程内读取，不进入命令行、网页、报告或Git记录。服务器主机公钥保存在 `config/ssh_known_hosts`，上传时拒绝未知或发生变化的主机密钥。

网页构建使用：

- `NEXT_PUBLIC_REPOSITORY_URL`：GitHub仓库地址。
- `NEXT_PUBLIC_REPORTS_RAW_BASE`：`public/reports` 对应的 raw.githubusercontent.com 地址。

密钥不会进入网页、报告或 Git 记录。
