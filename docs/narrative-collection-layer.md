# LINSC市场叙事采集层

## 定位

韭研公社作为独立的市场叙事采集层，负责采集、保留、去重和缓存个股异动解析、题材文章、市场帖子及传播记录。报告生成器只读取本层的结构化缓存，不在生成报告时临时依赖整站搜索。

## 数据分层

1. **原始页面层：** 保存页面HTML、页面地址、抓取时间、HTTP状态、内容哈希和可见文本。
2. **个股事件卡层：** 从原始页面拆出具体事件、事件类型、传播时间、个股映射、市场交易预期和价格反应。一只股票允许对应多个事件。
3. **题材聚合层：** 将事件连接到题材，分析扩散路径、核心与补涨、预期空间和持续性；聚合结果不能覆盖事件卡。

## 缓存目录

```text
data/cache/jiuyang/YYYY-MM-DD/
├── normalized.json
├── manifest.json
└── raw/
    ├── daily_action-<hash>.html
    ├── homepage-<hash>.html
    └── custom-<hash>.html
```

`normalized.json` 保存页面元数据、可见文本、结构化 `actions`（异动解析）和 `articles`（帖子/文章）、事件卡和传播记录；`currentPages` 始终指向本次最新页面，`pages` 保留历史版本；`raw/` 保存原始页面，便于回放和重新提取。重复采集同一页面时按URL和内容哈希去重；页面更新时追加新版本，不删除旧版本。

登录态采集时，采集器通过专用浏览器会话调用韭研页面自身的异动接口，按 `priorityStocks` 优先拉取全部异动分组，再读取首页结构化帖子，并只保存文章标题、正文、发布时间、股票显式映射和来源版本等研究所需字段。`manifest.json` 和 `normalized.json` 同时记录 `loginVerified`、`searchedPriorityStocks`、`actionCoveredPriorityStocks`、`articleCoveredPriorityStocks`；`extractionCoverage.noEvidenceStocks` 保留没有有效证据的涨停票，不能用模型推测填充。

事件卡提取采用“股票明确提及”规则：只有正文或页面线索明确出现优先股票名称/代码时才建卡，保存前后原始片段、页面哈希和时点证据。脚本不根据题材标签、封板时间或模型常识补写具体事件；预期差、催化窗口等不能从原文直接取得的字段保留为空，交给后续分析层处理。

## 采集范围

- 每日异动解析页：交易日午间和收盘前后的版本。
- 当日涨停股、1进2候选、高标和情绪负反馈股的定向页面（通过 `--url` 或后续检索步骤补充）。
- 热点题材、板块文章、每日复盘和热榜帖子。
- 可用时保存热度、互动和传播时间，用于判断叙事扩散强度。

采集器入口（默认优先读取同日 `data/cache/ftshare/YYYY-MM-DD/objective.json` 中的涨停池；登录会话由专用浏览器提供）：

```text
npm run narratives:collect -- --date YYYY-MM-DD
```

涨停池会写入缓存的 `priorityStocks`，供后续个股事件提取步骤优先检索；如已有明确的个股或题材公开页面，可通过多个 `--url` 参数放在本轮队列最前。采集器默认单线程、请求间隔2.5秒，可用 `--delay-ms` 调整；出现403、429、验证码或“查阅次数达到上限”时立即停止本轮，不自动重试。未验证登录的公共页面只标记为 `partial`，不能作为完整个股事件覆盖。采集失败只记录在 `manifest.json`，不伪造事件内容。

报告生成前会自动执行一次同日补抓：即使盘中没有启动监控，点击网页生成报告时也会先获取行情、构建涨停优先清单并运行本采集器，然后才进入大模型报告生成。

手动启动方式：

```text
npm run narratives:collect -- --date YYYY-MM-DD
```

手动采集只负责更新缓存，不生成报告、不渲染PDF、不上传服务器。

只重新提取事件卡而不访问网站：

```text
npm run narratives:extract -- --date YYYY-MM-DD
```

## 盘中持续监控启动器

Windows用户可以直接双击项目根目录的 `启动盘中持续监控采集.cmd`。启动器会：

1. 打开一个韭研公社专用浏览器窗口，登录状态保存在本机 `.local/jiuyangongshe-browser/`。
2. 等待用户确认登录后启动监控。
3. 每60秒查询一次FTShare涨停池，只记录新出现且符合LINSC股票范围的涨停票。
4. 新涨停进入待采集队列；第一批立即执行，后续默认按30分钟冷却时间批量执行，每日最多8批，避免每只股票触发一次网站访问。
5. 浏览器登录会话通过本机调试端口读取，只写入被Git忽略的本地会话文件；程序不读取或保存账号密码。
6. 15:10后完成待处理补抓并自动退出；手动停止可在监控窗口按 `Ctrl+C`。

命令行启动方式：

```text
npm run narratives:watch
```

盘中状态保存在 `data/cache/jiuyang/YYYY-MM-DD/intraday-state.json`，涨停快照保存在同目录的 `intraday-limit-up.json`。重复启动会读取已有状态，不会把已经识别的涨停再次当成新事件。

## 报告使用规则

- 题材模块先写具体事件，再写个股映射、扩散路径、逻辑和预期。
- 1进2模块第一段写具体异动事件，第二段写帖子传播和预期差。
- 同一题材下的不同事件不得合并成一句泛化概念；同一事件被多篇帖子重复传播时，合并事件主体但保留传播记录。
- 找不到个股异动解析时，使用有效的板块文章或其他帖子补写，不在报告中展示“未取得”。
- 完全没有有效事件证据的股票，不纳入1进2候选；不得依据题材名称、封板时间或股性反推消息。

## 边界

缓存用于个人研究和报告生成。原始内容不直接作为线上全文转载；报告采用精确归纳、必要的短语引用和事件映射。采集频率应尊重网站访问限制和服务协议。

不使用代理轮换、伪造用户身份、绕过登录或验证码等方式规避访问限制。需要更高额度时，应优先申请平台授权、接口或白名单。
